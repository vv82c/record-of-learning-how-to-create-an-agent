# ZCode 开源仓库架构分析

> 仓库：https://github.com/zai-org/ZCode （Z.ai 官方，4800+ star）
> 克隆时间：2026-09-21 · 版本 v3.14.0 · 许可证 Apache-2.0
> 本目录所有文件（含克隆的 `repo/`）均为本次调研产生，可整目录删除。

## 一、项目概况

ZCode 是 Z.ai（智谱）的 AI 编程工作台，对标 Claude Code / Cursor，是 **GLM 系列模型的官方 Agent Harness**。一个仓库同时产出三种形态的产品，共享同一套 Agent 运行时：

| 入口 | 形态 | 启动方式 |
| --- | --- | --- |
| **Desktop** | Electron 桌面应用 | `pnpm dev:desktop` |
| **Web / 命令行版** | 浏览器工作台 + 终端 TUI，无需 Electron | `zcode --web` / 直接 `zcode` |
| **Agent CLI** | 终端 Agent（也为桌面/Web 提供运行时） | `pnpm --filter @zcode/cli dev` |

- **规模**：约 **84.2 万行 TypeScript**，3866 个 ts/tsx 文件（不含 node_modules/dist/类型声明）。packages 层 54.3 万行，apps（CLI）层 29.1 万行。
- **开源方式特别**：git 历史只有一条提交 `feat: open source`（2026-09-21 squash 发布），即把内部仓库压缩为单一提交公开，无历史演进记录。
- **技术栈基座**：Node.js ≥24、pnpm 10 monorepo、TypeScript 6、React 19.2、Tailwind 4、Electron 41、Hono、node:sqlite、Vite 8、esbuild/tsup。
- **值得注意的缺失**：`packages/zcode-cua`（Computer-Use 桌面/浏览器控制）在开源版中是 **API 兼容的 fail-closed 占位包**——只有 .d.ts 接口声明，运行时全部不可用，真实 CUA 实现未开源。

## 二、总体分层

```
┌─────────────────────────────────────────────────────────┐
│  前端形态层（三选一）                                      │
│  packages/desktop (Electron)   packages/web   TUI(OpenTUI)│
├─────────────────────────────────────────────────────────┤
│  共享 UI / 客户端 SDK                                     │
│  packages/ui (1477 文件)    packages/client (WS/MessagePort)│
├─────────────────────────────────────────────────────────┤
│  服务与协议层                                             │
│  packages/server (Hono HTTP+WS)   packages/rpc (VSCode式IPC)│
│  packages/shared (zod 协议 ~3700行 + v4 wire 编解码)       │
│  packages/services (业务+SQLite持久化, 298 文件)           │
├─────────────────────────────────────────────────────────┤
│  Agent 运行时层  apps/zcode-cli (~1400 文件, 29万行)       │
│  core(状态机/工具/权限/压缩/子代理) · adapters(模型/MCP/存储)│
│  tui · cli · dynamic-workflow · node-repl-host ...        │
├─────────────────────────────────────────────────────────┤
│  模型接入                                                 │
│  CLI: Vercel AI SDK (anthropic/openai/openai-compatible)  │
│  产品层: packages/provider(+node) 自研 Registry/OAuth      │
└─────────────────────────────────────────────────────────┘
```

关键关系：Desktop 通过 **stdio 子进程**拉起 Agent；Web 通过 **WebSocket** 连 server；RPC 框架同时支持 Electron MessagePort 与 WS 两种传输。手机远控复用同一 HTTP+WS + token，不另起 Agent。

## 四、Agent 内核（最有学习价值的部分）

**主循环 = 显式状态机**，`apps/zcode-cli/packages/core/src/agent/turn-machine.ts`：

```
ProcessingInput → ModelRequest → Streaming → ScheduleTools
    → ExecutingTools → Permission → Aggregating → (回到 ModelRequest | Complete/Fail)
```

- 真正的执行编排：`core/src/runtime/agent-runtime.ts` + `runtime/methods/turn.ts`（executeTurn）：用户输入 → context builder 组装上下文 → `adapters/src/model/runner.ts` 流式调 LLM → tool call 经 `core/src/tool/scheduler.ts` 调度（同批并发）→ 结果回填消息史 → 循环直到模型不再调工具。
- **工具系统**：`core/src/tool/registry.ts` 注册表 + `handlers/`（100+ 文件）。内置工具覆盖 Read/Write/Edit、Bash、Glob/Grep、WebFetch/WebSearch、node_repl（JS 执行宿）、Task/Agent（子代理）、Skill、TodoWrite、AskUserQuestion、CreateWorkflow 系列、图像/PDF/视频读取。
- **权限模型**：`core/src/permission/broker.ts`（broker/service/rule-matching 三件套），allow/deny 规则可持久化；执行侧有 `approval-gate.ts` 审批门。Bash 有专门的只读判定策略表（`bash-readonly-policy-*.ts`）。
- **上下文管理**：`core/src/compact/`——默认 200K 窗口，autocompact 阈值 + microcompact 两级压缩。
- **子代理**：`core/src/subagent/`（runner、explore、general-purpose，profile 走 frontmatter 定义）。
- **MCP**：客户端在 `adapters/src/mcp/`（stdio 传输、OAuth、Windows Job Object 进程管控），桥接为工具在 `core/src/mcp/index.ts`。
- **扩展体系**：Skills（`adapters/src/skills/scan.ts` 扫描 + skills-lock.json）、插件商店（插件含 commands/agents/skills/hooks/mcpServers，见 CONTEXT.md 术语表）、workspace hooks 信任链（`workspace-hook-trust-*.ts`）。
- **动态工作流**：`dynamic-workflow` 包是 TS 脚本引擎，用户脚本经类型检查后编排多子代理（带 phase 图、journal 缓存、artifact 发布）。

## 五、服务端与协议

- **server 用 Hono**（不是 express/fastify）：`packages/server/src/http.ts` 是路由中枢——`GET /api/server-info`、`POST /api/rpc-host-capability`（可信 host 凭证签发）、`GET /ws`（终端客户端）、`GET /ws/host`（可信 host）、`POST /api/connect-remote` + `GET /ws/remote/:id`（远程桥接）、token 认证。
- **RPC 框架**（`packages/rpc`）是照着 VS Code 的 IPC 分层自研的：foundation（Event/CancellationToken）→ buffer（VSBuffer）→ protocol（IMessagePassingProtocol + ChunkStream 粘包）→ channelServer/channelClient（多路复用通道）→ proxy-channel/serialization → ipc（Electron MessagePort）/remote。`rpc/examples/` 有 4 个可跑示例。
- **协议**：`packages/shared/src/zcode-protocol/index.ts` 用 zod 定义全部消息（Request/Notification/Response/Error，方法命名空间：session 21 个、workspace、provider、usage、mcp…），带 requestId/trace；`zcode-protocol-v4/` 是 wire 级编解码（delta/snapshot/transport/workflow-runs），供远控断线重放（replayable）。
- **持久化**：`packages/services` 用 **node:sqlite（DatabaseSync，Node 原生）**，`src/session/tasksDatabase/` 含 schema-v1/migrations/prepared statements；还兼容读取 Claude 的会话文件格式（`claude-native/`）。
- **远程开发**：`packages/server/src/remote/` 支持 SSH/WSL/Docker 三种 backend，把 agent bundle 部署到远端机器，远端服务经 `/ws/remote/:id` 桥回本地浏览器——本地 UI 操作远程 workspace 的完整链路。

## 六、模型接入（双层设计）

1. **CLI Agent 运行时层**（`apps/zcode-cli/packages/adapters`）：用 **Vercel AI SDK**（@ai-sdk/anthropic、openai、openai-compatible，根目录还带 patches 修上游），支持 anthropic-messages / openai-responses / openai-chat-completions 三种 wire 协议。GLM 走 `official-coding-plan-gateway.ts`（open.bigmodel.cn 的 Anthropic 兼容端点 + ultra-zai 网关）。runner.ts 封装流式、重试、空闲超时。
2. **产品配置层**（`packages/provider` + `provider-node`）：**自研、零 AI SDK**——zod 定义 provider 配置 schema、resolver 产出 Registry（baseUrl → OpenAI 兼容 HTTP）、账户级 OAuth（`account:zai-*` / `account:bigmodel-*` 套餐）、内置 provider 配置下载物化。内置配置见 `config/provider/zcode-builtin.json`。

自定义 baseUrl 即可接任何 OpenAI 兼容服务。

## 七、工程治理（这份仓库的"管理方式"本身很值得学）

- **架构即代码**：根目录 `architecture-policy.yaml` 声明每个模块的 roots/依赖方向/公开入口/分层（domain→app→adapters，domain 层禁 IO）、owner；`scripts/architecture/architecture-check.mjs` 做环检测 + 违规 sha256 指纹 + 基线比对（`.architecture-baseline.json`），**只对新违规报错**（存量违规进基线，增量必须干净），挂在 pre-push 钩子。硬限制：单文件 ≤400 行、契约文件 ≤300 行、公开方法 ≤12、禁循环依赖、禁深导入。
- **spec-first 开发规则**（AGENTS.md）：改行为先改 spec；bug 修复必须用中文注释说明原因和依据；必须跑 typecheck+lint 并如实报告结果。
- **DESIGN.md**：30KB 的 UI 设计系统（语义色 token、text-ui-* 字号阶梯、圆角嵌套层级、密 information density 原则），要求 agent 写 UI 前先读它。
- **CONTEXT.md**：领域术语表（当前是插件商店词汇），统一命名、禁用词。
- **自举工具链**：`.agents/skills/` 里有 architecture-governance、react-best-practices、electron 等 8 个 skill 喂给 AI 开发者。
- **安全细节**：WebFetch 出口防护（egress guard）、bash 只读白名单生成脚本、MCP Windows Job Object、存储层故障注入测试（fs-fault-injection）、hook 信任链。

## 九、点评：架构上最值得借鉴的三点

1. **一套 Agent 内核喂三种前端**：TUI/Web/Desktop 共享同一个 runtime，协议层（zod + v4 wire codec + replayable delta/snapshot）是唯一事实来源，所以"手机远控桌面"这种功能只需复用 attachment，不另起 Agent。
2. **治理机制为 AI 协作而生**：架构检查只罚增量、spec 先行、DESIGN/CONTEXT 当作 agent 的系统提示词——这个仓库本身就演示了"如何管理一个主要由 AI 写代码的代码库"。
3. **诚实的开源边界**：CUA 直接给 fail-closed 占位包 + NOTICE.md 声明，不开源的部分明确说不开源，而不是藏掖。
